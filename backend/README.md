# Backend — зона Дмитрия Богданова

Серверная часть кредитного кабинета Milk Tower: сессии и роли, API заявок, механизм состояний, имитации проверок и объяснимый скоринг-рекомендация. Всё работает только на синтетических данных.

Стек: Python 3.12, FastAPI, SQLAlchemy 2, Alembic, SQLite (`$DATA_DIR/app.db`), pytest, ruff, uv (`uv.lock`).

## Запуск и проверки

Из каталога `backend/`:

    uv sync
    uv run pytest -q
    uv run ruff check .
    DATA_DIR=/tmp/mt-data uv run uvicorn app.main:app --port 8000

Проверка: `curl localhost:8000/healthz` → `{"status":"ok"}`.

Настройки (переменные окружения): `DATA_DIR` (по умолчанию `/data`), `ML_BASE_URL` (читается, пока не используется), `COOKIE_SECURE`, `CORS_ORIGINS`, `DEMO_LOGIN_ENABLED`.

## Вход и роли

Во frontend нет формы входа, он только проверяет серверную сессию (`GET /session`). Поэтому сессию выдаёт демо-ссылка (пароля нет, только синтетические пользователи):

    GET /api/v1/demo/login/{login}?next=<адрес frontend>

| Логин | Роль | Кто |
|---|---|---|
| `volkov` | client | Александр Волков, владелец заявок из seed |
| `ivanova` | client | Мария Иванова, без заявок (проверка «чужих» заявок) |
| `smirnova` | employee | Елена Смирнова, кредитный специалист |

Сессия — cookie `session` (HttpOnly, SameSite=Lax), в БД хранится только хэш токена, срок 12 часов. Демо-вход отключается переменной `DEMO_LOGIN_ENABLED=false`.

Проверка с frontend без правок его кода (используйте `localhost`, не `127.0.0.1`):

1. Backend: `DATA_DIR=/tmp/mt-data uv run uvicorn app.main:app --port 8000`.
2. Frontend: `cd frontend && VITE_API_MODE=http VITE_API_BASE_URL=http://localhost:8000/api/v1 npm run dev`.
3. Открыть `http://localhost:8000/api/v1/demo/login/volkov?next=http://localhost:5173/`, нажать «Проверить серверную сессию». Для сотрудника — выйти через профиль и открыть ссылку с `smirnova`.

## API (префикс `/api/v1`)

| Метод и путь | Назначение |
|---|---|
| `GET /session`, `DELETE /session` | Текущая роль, выход |
| `GET /demo/login/{login}` | Демо-вход (расширение контракта) |
| `GET /applications`, `POST /applications` | Список, создание черновика |
| `PATCH /applications/{id}`, `DELETE /applications/{id}` | Правка и удаление черновика |
| `POST /applications/{id}/documents`, `DELETE .../documents/{docId}` | Документы (PDF/JPG/PNG, до 10 МиБ) |
| `POST /applications/{id}/actions` | Единственная точка смены статуса: `{action: "<новый статус>", ...}` |
| `GET /healthz` | Готовность, без авторизации |

Ошибки всегда JSON `{code, message}`: frontend показывает `message`.

## Права доступа

Клиент видит и меняет только свои заявки (чужая или несуществующая — 404). Сотрудник видит все заявки, кроме черновиков. Нет сессии — 401, действие чужой роли — 403.

## Состояния заявки

    draft → submitted → manual_review → needs_info → submitted
                                      → approved → issued
                                      → rejected

`rejected` и `issued` — конечные. Правила описаны в одном месте — `app/state_machine.py`. Повторное или конкурирующее действие получает 409 и не дублирует историю (смена статуса — условный `UPDATE`). Каждый переход пишет событие истории и запись аудита. Переход `submitted → manual_review` (кнопка «Завершить демо-проверки») запускает проверки.

## Проверки и кредитная логика

- Имитации ЕГРЮЛ, БКИ и комплектности документов (`app/checks.py`) детерминированы по ИНН: ИНН на `0` — «компания в ликвидации»; по последним трём цифрам определяется результат БКИ. Внешних запросов нет.
- Скоринг (`app/scoring.py`, правила `rules-v1`) даёт балл 0–1000, рейтинг, рекомендацию и объяснимые факторы `{label, positive, impact}`. Пороги и веса — рабочие допущения.
- Рекомендация скоринга статус не меняет. Решение (одобрить, отказать, запросить сведения) — отдельное действие сотрудника: пишется в таблицу `decisions`, расхождение с рекомендацией помечается в `audit_log`.
- Лимиты продуктов, ставки и аннуитет (`app/credit.py`) повторяют `frontend/src/domain/application.js`. Расчёт `calculation` всегда считает сервер.

## Данные и миграции

Миграции Alembic применяются при старте. Таблицы: пользователи, сессии, заявки, проверки, решения, аудит. История, сообщения и документы хранятся в заявке как JSON в формате frontend. Содержимое загруженных файлов не хранится, только метаданные.

`app/seed.py` — **временная заглушка для тестов** (3 пользователя и 4 заявки в разных статусах). Реальные синтетические данные готовит Михаил, при замене достаточно сохранить формат заявки из `docs/openapi.json`.

## Допущения и ограничения

- Демо-вход без пароля подходит только для синтетических данных.
- Защита от CSRF опирается на `SameSite=Lax` и CORS-список `CORS_ORIGINS`: frontend не отправляет CSRF-токен, а менять его нельзя.
- ML-сервис не подключён: скоринг работает внутри backend за функцией `score_application`.
- Сборка Docker-образа и запуск на read-only файловой системе в этой версии README не проверялись.
- Три строки «ЕГРЮЛ / БКИ / Комплектность» и плашка «Демонстрационные результаты» на вкладке проверок зашиты во frontend; backend отдаёт реальные баллы и факторы.
