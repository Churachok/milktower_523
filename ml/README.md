# ML — зона Михаила Уляхина

Здесь размещаются подготовка признаков, скоринг, inference-сервис, его тесты, lock-файл и CPU `Dockerfile`. Сейчас модели и inference-кода нет; результат в frontend-демо — синтетическая константа, не прогноз ML.

## Подготовленная интеграция

`compose.integration.yaml` ожидает сервис `ml` на `0.0.0.0:8001`, с `GET /healthz` → 200 **после загрузки модели**. В образе нужен `curl` для healthcheck. Бэкенд обращается по внутреннему адресу `http://ml:8001`; порт ML наружу не опубликован. Контракт inference endpoint, входных признаков и ошибок согласуют Михаил и Дмитрий.

Frontend ожидает от backend поле `checks` следующего вида; это UI-контракт, а не требование к типу модели:

```json
{
  "score": 768,
  "rating": "A",
  "recommendation": "Рассмотреть одобрение",
  "factors": [{ "label": "Пример объясняющего фактора", "positive": true }]
}
```

Шкала в предлагаемом OpenAPI — 0–1000. Если модель выдаёт вероятность или другую шкалу, преобразование и смысл рейтинга согласуются с backend. Скоринг предоставляет рекомендацию; итоговое кредитное решение остаётся отдельной бизнес-логикой.

## Контракт контейнера и ресурсы

| Пункт | CPU-режим по умолчанию |
|---|---|
| Сборка | `ml/Dockerfile`, установка из lock-файла, непривилегированный пользователь |
| Вычисление | `ML_DEVICE=cpu`, CUDA скрыта, лимиты 2 CPU / 3 ГиБ, BLAS/OpenMP по 2 потока |
| Запись | `/cache` и `/tmp`; корневая файловая система read-only |
| Кэш | `XDG_CACHE_HOME=/cache`, `HF_HOME=/cache/huggingface`; образ создаёт `/cache` с правами пользователя приложения |
| Модель | Весам и runtime нужно помещаться в лимит вместе; холодный запуск и пиковую память измеряет ML-разработчик |
| Автономность | Модель включена в воспроизводимую сборку; работа inference не требует внешнего платного API или скачивания при каждом старте |

Опционально подготовлен [compose.gpu.yaml](../compose.gpu.yaml) для одной NVIDIA GPU. Для его использования Михаил добавляет `ml/Dockerfile.gpu` с совместимым runtime и поддержкой `ML_DEVICE=cuda`. CPU остаётся обязательной базой для обычного ПК. Другие видеокарты могут использовать CPU-режим.

## Что заполнить перед сдачей

| Раздел ML | Заполняет Михаил |
|---|---|
| Подход | Правила / балльная модель / ML, признаки и обоснование выбора |
| Воспроизводимость | Версии runtime и зависимостей, модель, версия, источник, лицензия и SHA-256 артефактов |
| Данные | Происхождение и лицензия; для публичного демо только синтетические данные |
| Качество | Метод проверки, метрики, ограничения и интерпретация факторов |
| API | Вход/выход, endpoint, таймаут, ошибки; согласование с backend |
| Окружение | Измеренные время старта, память и задержка на CPU; GPU — дополнительный вариант |
| Материалы | [Манифест модели](models/README.md), обновлённые THIRD_PARTY_NOTICES и общая архитектура |

Кейс допускает правила вместо сложной ML-модели; ИИ не обязателен. Если используется LLM, по кейсу допустимы только открытые веса. Сырые датасеты, кеши, checkpoints и большие веса не входят в Git. При этом жюри должно получить воспроизводимый способ загрузки проверенного артефакта во время сборки — см. [models/README.md](models/README.md).
