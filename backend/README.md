# Backend — зона Дмитрия Богданова

Здесь размещаются серверная реализация, её тесты, lock-файл, миграции и `Dockerfile`. Стек и база данных остаются на выбор backend-разработчика. Сейчас в каталоге есть только договорённости по интеграции; работающий API ещё не добавлен.

## Что уже подготовлено со стороны frontend

- [OpenAPI 3.1](../docs/openapi.json) — предлагаемый контракт `Application`, сессий, документов и действий.
- [Коллекция запросов](../docs/requests.http) и [модель данных / состояния](../docs/architecture.md).
- HTTP-адаптер в `frontend/src/services/api.js`, обработка таймаутов и ошибок, cookies с `credentials: include`.
- Nginx в Docker-режиме `integration` передаёт `/api/v1/...` на `http://backend:8000`, сохраняя путь и origin браузера.
- `compose.integration.yaml`: сборка из этого каталога, именованный том `/data`, лимиты 1 CPU / 1 ГиБ, `ML_BASE_URL=http://ml:8001`.

## Контракт контейнера

| Пункт | Ожидание |
|---|---|
| Файл сборки | `backend/Dockerfile`, установка зависимостей из lock-файла |
| Процесс | Непривилегированный пользователь, HTTP на `0.0.0.0:8000` |
| Готовность | `GET /healthz` без авторизации → 200 после инициализации хранилища; в образе установлен `curl` для healthcheck |
| API | Префикс `/api/v1`; контракт выше согласовывается перед реализацией |
| Данные | `DATA_DIR=/data`, запись в этот том и `/tmp`; корневая файловая система read-only |
| ML | Внутренний адрес из `ML_BASE_URL`, таймауты и обработка недоступности сервиса |
| Хранилище | Образ заранее создаёт `/data` с правами пользователя приложения; если нужна отдельная СУБД, добавить сервис, healthcheck, миграции и бюджет памяти в Compose |

Перед полным прогоном нужно согласовать выдачу демонстрационной серверной сессии для обеих ролей. Сейчас frontend в HTTP-режиме умеет проверить `GET /session` и завершить `DELETE /session`; серверный вход и создание сессии ещё не реализованы. Основной сценарий должен проходить внутри продукта, без почты/SMS. Сервер проверяет роли и переходы, повторно валидирует входные данные и файлы.

## Что заполнить перед сдачей

| Раздел backend | Заполняет Дмитрий |
|---|---|
| Язык, runtime и библиотеки | Точные версии, lock-файл и команды тестирования |
| Сессии и демо-пользователи | Способ входа, роли, синтетические учётные записи |
| Данные и миграции | СУБД, инициализация, синтетический seed, хранение файлов |
| Бизнес-логика | Валидация, переходы, решение отдельно от ML-рекомендации |
| Интеграция с ML | Согласованные запрос/ответ, таймауты и ошибки |
| Материалы | Актуализированные OpenAPI, HTTP-примеры и THIRD_PARTY_NOTICES |

После добавления реализации общий запуск описан в [docs/docker.md](../docs/docker.md). Рабочие БД, uploads, локальные env и виртуальные окружения исключены из Git. Для воспроизведения жюри нужны миграции и синтетический seed в исходниках, а не копия рабочей базы.
