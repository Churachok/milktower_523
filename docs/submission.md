# Комплект сдачи Milk Tower 1.1.0

Кейс, страница 7, требует GitHub с историей и однозначный идентификатор версии до дедлайна. Рекомендуемая метка этой подготовки — **`submission-2026-10-26`**. Точный hash не записывается внутрь собственного коммита: после фиксации он автоматически попадает в сдаваемый архив, Docker-образы и API версии.

## Что передать жюри

- Репозиторий: [Churachok/milktower_523](https://github.com/Churachok/milktower_523). Он публичный; отдельный доступ `alfa-hack-2026` не нужен.
- Полный commit из `SUBMISSION.json` / `SOURCE_COMMIT` и тег `submission-2026-10-26`.
- Архив `milk-tower-1.1.0-<commit>.tar.gz` и соседний `.sha256`; внутри находятся исходники, lock-файлы, Docker, fixtures, миграции, документация, `START-HERE.md` и `MANIFEST.sha256`.
- Проверку CI именно этого commit; ссылка доступна во вкладке GitHub Actions. Workflow `Submission package` дополнительно собирает и проверяет архив для тега.

В архив не входят секреты, `.git`, зависимости, build-кэш, рабочая БД и пользовательские файлы. Больших весов нет: основной скоринг использует локальные правила. История коммитов остаётся в GitHub; архив является экспортом точной версии.

## Самостоятельный запуск жюри

Нужны Docker с Compose 2.20+ и Git Bash / Bash. На обычном ПК с 4 CPU / 8 ГБ ОЗУ GPU не нужен. Первая сборка требует интернет для публичных образов и пакетов; собранный продукт работает без внешних API и ключей.

```bash
# Вариант из Git:
git clone https://github.com/Churachok/milktower_523.git
cd milktower_523
git checkout submission-2026-10-26
./scripts/run.sh

# Либо распаковать архив, проверить MANIFEST.sha256 и выполнить тот же run.sh.
```

Открыть [http://localhost:8080](http://localhost:8080). Учётные роли: предприниматель Александр Волков (`volkov`) и сотрудник Елена Смирнова (`smirnova`), без пароля внутри синтетического демо. Другой клиент `ivanova` доступен для API-проверки изоляции. Основной маршрут — [README](../README.md#сценарий-проверки).

- [Swagger](http://localhost:8080/api/v1/docs) загружается локально, без CDN; запросы используют серверную cookie.
- [Версия backend](http://localhost:8080/api/v1/version) и [версия frontend](http://localhost:8080/version.json) должны содержать один и тот же полный commit.
- `docker compose down` сохраняет заявки в томе. `down -v` удаляет данные.

## Регламент заморозки версии

Перед фиксацией выполнить [локальные проверки](verification.md), затем:

```bash
git status --short
git add <проверенные-файлы>
git diff --cached --check
git commit -m "feat: prepare reviewed submission"
git push origin main
# Дождаться успешного CI для этого commit.
git tag -a submission-2026-10-26 -m "Milk Tower reviewed hackathon submission"
git push origin submission-2026-10-26
node scripts/package-release.mjs .local/submission
```

Команда упаковки требует чистое дерево, Node.js 22+ и GNU tar. Она экспортирует только Git HEAD, фиксирует его commit/tree, считает SHA-256 всех файлов и контрольную сумму tar.gz. При повторной упаковке той же версии и того же тега архив воспроизводим побайтно. Проверка после распаковки: `node scripts/verify-package.mjs <каталог>` или `sha256sum -c MANIFEST.sha256`.

Не перемещать опубликованный тег на другой commit. Для исправлений создавать новую метку и отдельно сообщать новый идентификатор организаторам, если это допускает дедлайн. В PDF нет календарной даты дедлайна — её нужно брать из объявления организаторов.

## Сценарий демонстрации на 5–7 минут

1. Публичный калькулятор → 2,4 млн ₽ / 18 месяцев → вход → один черновик с этими условиями.
2. Финансы 12 млн / 7 млн / долг 0 / возраст 3 года; включить сценарий снижения выручки и показать допущения.
3. Загрузить два PDF из `docs/fixtures`; чек-лист покажет комплект. Отправить заявку.
4. Во втором браузере войти сотрудником, дождаться обновления очереди, выполнить скоринг и показать объяснения.
5. Запросить сведения. У клиента без ручной перезагрузки появится запрос; ответить и выполнить повторный скоринг сотрудником.
6. Предложить 2 млн / 24 месяца / 20%; клиент сравнивает и подтверждает моделируемую выдачу.
7. Показать сохранение после перезагрузки, персональную ленту и совпадающие commit в версиях frontend/backend.

Другой исход — мотивированный отказ — описан в [test-scenarios.md](test-scenarios.md). Все действия происходят внутри продукта.

## Выкладка и оставшиеся ограничения

Для внешнего сервера готов [HTTPS-шлюз](../deploy/README.md) с отдельным паролем просмотра. Фактической облачной публикации пока нет: нужны сервер, домен, DNS и доступ. По кейсу это дополнительная рекомендация, а не обязательная часть сдачи.

Проверяемая база не зависит от Groq; optional AI endpoints не нужны для демонстрации. Точность кредитного риска, промышленная авторизация, хранение содержимого документов и горизонтальное масштабирование не заявляются. Полная сверка требований и приоритеты — [requirements.md](requirements.md).
